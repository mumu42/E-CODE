# 七期任务规划（Phase 7：云化、社交与商业化扩展）

> 更新日期：2026-08-25
> 备注：Phase 1-6 已完成本地私有 AI 英语学习核心闭环（目标选择、自适应测评、听说读写、词汇、模考、AI 顾问、进度、离线、真题、AI 语音对话、移动端 PWA、多语言）。本期在保留“本地优先、完全私有”理念的前提下，逐步引入可选的云化、社交与商业化能力，把产品从单机工具升级为可持续运营的学习平台。

---

## 1. 目标

在六期已有本地闭环基础上，进一步扩展：

1. **用户账号与鉴权**：支持注册/登录，区分游客与登录用户，保护个人数据。
2. **云端同步与多设备共享**：在端到端加密前提下，实现学习记录、档案、错题本跨设备同步。
3. **学习社群与排行榜**：通过打卡、挑战、排行榜提升用户粘性与学习动力。
4. **付费订阅与会员体系**：提供基础免费 + 高级会员能力，支撑长期运营。
5. **实时视频 / AI 真人外教**：从语音对话升级到视频互动，提供更沉浸的练习体验。
6. **原生应用商店发布**：完成 iOS / Android 应用商店上架流程，扩大用户覆盖。

---

## 2. 范围边界

### 2.1 本期包含

- 用户注册 / 登录 / 鉴权（邮箱 / 手机号 / 第三方 OAuth）
- 端到端加密的数据云端同步
- 多设备登录与数据冲突处理
- 学习打卡、挑战、排行榜
- 基础社区互动（动态、评论、点赞）
- 免费 / 会员权益拆分
- 订阅、兑换码、订单管理
- 实时视频对话 / AI 虚拟外教
- iOS / Android 应用商店上架

### 2.2 本期不包含

- 学习社群的 UGC 内容审核自动化
- 真人外教实时授课（非 AI）
- 企业版 / 多租户
- 智能硬件接入
- 线下教学服务

## 4. 任务清单

### 任务 1：用户账号与鉴权

**目标**：建立可选的账号体系，让游客用户也能平滑升级为登录用户。

| 子任务 | 说明 | 状态 |
|--------|------|------|
| 1.1 账号数据模型 | 设计 `UserAccount`、`AuthSession`、`Identity` 类型 | 待开始 |
| 1.2 注册 / 登录 UI | 邮箱/手机号注册、登录、找回密码页面 | 待开始 |
| 1.3 第三方 OAuth | 支持 Google / Apple / 微信登录 | 待开始 |
| 1.4 JWT / Session 管理 | Access Token + Refresh Token，安全退出 | 待开始 |
| 1.5 游客模式兼容 | 本地档案可在登录后合并到账号 | 待开始 |

**验收标准**：

- 用户可以邮箱注册、登录、退出。
- 登录后原有本地档案可绑定到账号。
- 未登录游客仍可继续使用本地功能。

---

### 任务 2：云端同步与多设备

**目标**：在保护隐私的前提下，实现学习数据跨设备同步。

| 子任务 | 说明 | 状态 |
|--------|------|------|
| 2.1 同步数据模型 | 定义可同步的 `SyncRecord`、`SyncConflict` | 待开始 |
| 2.2 端到端加密 | 客户端加密 / 解密，服务端仅存储密文 | 待开始 |
| 2.3 增量同步策略 | 只上传变更，支持版本向量冲突解决 | 待开始 |
| 2.4 多设备登录管理 | 查看/踢出已登录设备 | 待开始 |
| 2.5 离线优先同步 | 离线时本地操作，联网后自动合并 | 待开始 |

**验收标准**：

- 用户在 A 设备练习后，B 设备登录可见。
- 服务端无法读取用户明文数据。
- 离线操作在联网后正确同步，冲突可处理。

---

### 任务 3：学习社群与排行榜

**目标**：通过社交化机制提升用户活跃度和学习动力。

| 子任务 | 说明 | 状态 |
|--------|------|------|
| 3.1 打卡动态 | 每日练习后生成可分享的打卡卡片 | 待开始 |
| 3.2 排行榜 | 周/月学习时长、连续天数排行 | 待开始 |
| 3.3 学习挑战 | 官方发起 7 天 / 21 天打卡挑战 | 待开始 |
| 3.4 基础社区 | 动态流、评论、点赞 | 待开始 |
| 3.5 隐私控制 | 用户可关闭分享、隐藏排行榜 | 待开始 |

**验收标准**：

- 用户可选择分享打卡到社区。
- 排行榜仅展示同意参与的用户。
- 社区内容支持举报与基础审核。

### 任务 4：付费订阅与会员体系

| 子任务 | 说明 | 状态 |
|--------|------|------|
| 4.1 会员权益设计 | 区分免费与会员可用功能 | 待开始 |
| 4.2 订阅管理 | 月付 / 年付订阅、续订、取消 | 待开始 |
| 4.3 兑换码系统 | 生成/验证兑换码，兑换会员时长 | 待开始 |

## 6. 验收标准（整体）

1. 用户可注册/登录，游客数据可绑定到账号。
2. 登录用户在不同设备间可同步学习数据，且服务端不可解密。
3. 打卡、排行榜、挑战功能可正常运行。
4. 会员订阅流程完整，权益边界清晰。
5. AI 视频对话可用，弱网可降级。
6. iOS / Android 应用商店上架完成。
7. `npm run lint` 和 `npm run build` 通过。

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| 端到端加密实现复杂，密钥管理易出错 | 使用成熟方案（如 Web Crypto + 派生密钥），充分测试恢复流程 |
| 多设备同步冲突难以避免 | 版本向量 + 最后写入者胜出 + 用户手动合并 |
| 社群内容审核成本高 | 先做最小社区，配合举报与人工复核 |
| 支付合规与税务复杂 | 优先接入 Apple/Google IAP，网页端用 Stripe |
| 视频对话延迟高 | 使用专业 RTC 服务，提供语音降级 |
| 应用商店审核周期长 | 提前准备素材与隐私政策，预留缓冲时间 |
